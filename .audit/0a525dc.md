**What the change actually did (for context):**
Task 147 delivery adds `CcxtExtract.DriftAudit.OverrideRawSources` (a tiny internal namespace module under DriftAudit) that holds a static v4-pointer → [raw source pointer(s)] map. `DriftAudit.stale_override_finding/4` (refactored out of the prior flat_map) now calls `OverrideRawSources.pointers/1` for the translated override path, diffs those raw sources (via the existing `safe_get`), and includes `raw_source_pointers` + `changed_raw_sources` (list of `%{pointer, before, after}`) in the finding's `details` when a mapped raw drifts. A stale_override is now emitted when *either* the final override-applied value differs from baseline *or* any mapped raw source differs (even if the final curated value is identical). Unknown override paths fall back to the prior final-value-only behavior (`pointers` returns `[]`). Mix task short description and DriftAudit moduledoc updated; CHANGELOG entry added at top of Unreleased. Three new unit tests lock the three cases (value drift still works and carries the new detail keys; raw drift alone with identical final value now correctly classifies as stale with snapshots; unrelated raw drift does not produce a false stale).
